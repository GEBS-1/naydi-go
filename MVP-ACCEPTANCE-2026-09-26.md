## Причина нулевых результатов в широком прогоне

Sonar часто возвращал категории, а не страницы Product/Offer. Узкий список разрешённых хостов, отсутствие адаптеров товарных блоков продавцов и буквальная проверка слов («лампочку»/«лампа», «корм»/«консервы», «беспроводные»/TWS) дополнительно отбрасывали реальные предложения. AggregateOffer всей категории нельзя считать ценой отдельного товара.

Добавлены ограниченные проверенные адаптеры Гомеовет, Velosky, iStudio; существующий парсер используется для Порядка. Это адреса источников, не массивы товаров. HTML загружается с проверкой robots, тайм-аутами, ограничением размера; цены связываются только с собственным товарным блоком. Каталоги кешируются в D1 на 30 минут. Достаточные предложения позволяют пропустить платный Sonar; достаточность учитывает бюджет. Каталоги региональные, только для Казани. Остатки и координаты из них не выдумываются.

## Экономика

Факт для 10 запросов пяти каталоговых категорий: 0 ₽ платных API, среднее первое обращение 7,033 с, повтор 3,517 с; кеш каталога использован в 50% обращений. OSM уже был закеширован. Это не полностью холодный старт инфраструктуры.

Прогноз для того же состава каталоговых запросов: 100 / 1 000 / 10 000 = 0 ₽ платных API, но НЕ нулевая стоимость эксплуатации. Нельзя переносить на произвольный веб-поиск или считать гарантией пропускной способности публичных серверов.

Иллюстрация другого состава: при одном Sonar-вызове около 0,64 ₽ на каждый некешированный поиск — примерно 64 / 640 / 6 400 ₽. При 50% кеша — 32 / 320 / 3 200 ₽. Это прогноз, не измеренный массовый прогон; подарочный запрос выше потребовал три вызова Sonar. Фото, Qwen, хостинг и дополнительные вызовы оплачиваются отдельно.

Месячный предел теперь задаётся `API_MONTHLY_LIMIT_RUB` без верхнего потолка 3 000. По умолчанию 3 000; 0 запрещает платные вызовы; некорректное значение закрывает платный доступ. Резервы, неизвестная стоимость, ограничения повторов и одного вызова сохранены. Ограничение приложения не заменяет лимит в аккаунте RouterAI.

## Подключение первого магазина и запуск

Существующий процесс: администратор создаёт закрытую карточку/товары → персональный preview → согласование и подтверждение данных → публикация администратором → одноразовое приглашение владельцу → серверная сессия → редактирование собственного каталога. Отправка ссылки ручная, автоматической почты нет. Неподтверждённые пять витрин не публиковались.

Настройки: серверные `ROUTERAI_API_KEY`, `ROUTERAI_MODEL=qwen/qwen3-30b-a3b-instruct-2507`, `ROUTERAI_WEB_MODE=sonar`, `API_MONTHLY_LIMIT_RUB`, `API_MAX_CALL_RUB`; существующие D1/R2 bindings и `ADMIN_EMAIL`. Sonar: `perplexity/sonar`; Vision: `qwen/qwen3-vl-8b-instruct`. Brave не требуется. `AUTH_TRUSTED_PROXY` включать только за реально проверяющим пользователя шлюзом, который удаляет поддельные identity-заголовки; локальный mock не является production-авторизацией. Полный шаблон — `.env.example`.

Блокеры публичного запуска:
1. Браузерная приёмка A–F на мобильной/десктопной ширине, фото и UI owner CRUD с публикацией. Серверный owner CRUD уже проверен.
2. Проверка production identity-шлюза/администратора, HTTPS/cookie, origin и D1/R2 bindings в целевом окружении. Production в этом проходе не проверялся.
3. Локальные D1/R2 backup успешно проверены вечером, см. дополнение выше. Перед применением миграций в production нужны отдельные проверенные production D1/R2 backups и пробное восстановление. Миграций в этом проходе нет.
4. Публичные Overpass/геокодер/Valhalla не имеют SLA; для массовой нагрузки нужен согласованный сервис/собственный экземпляр. Нужен контроль прав и условий выбранных каталогов; robots — техническое ограничение, не лицензия на изображения. Чужие фото не копируются.
5. Покрытие ограничено источниками; подарки с бюджетом пока часто без подтверждённых цен. Интернет целиком не индексируется. Привязка товаров к филиалам возможна только при достаточных доказательствах.

Рекламный слот сохранён: нейтральный без рекламодателя, без задержки и фиктивных показов; структура маркировки есть, рекламный кабинет/оплата не подключены.

От владельца сейчас не нужен новый RouterAI-ключ. Нужны подтверждение production-конфигурации, бюджета и отдельное разрешение на деплой ПОСЛЕ закрытия перечисленных блокеров.
