# Регистрация магазинов: только Telegram и MAX

ВКонтакте исключён из входа по решению владельца проекта. Его кнопки, OAuth-маршруты
и настройки удалены. Исторические миграции сохранены: записи базы не удаляются.

Путь продавца: подтвердить вход в Telegram/MAX → создать магазин и точку → добавить
товары → подтвердить данные и согласие → отправить на проверку → после одобрения
появиться в поиске. Один аккаунт — одна организация и одна точка на карте.

В PostgreSQL сохраняются ID аккаунта, подтверждённые идентификаторы Telegram/MAX,
имя, хеш сессии и способ входа, магазин, товары и заявки. Сессия действует 30 дней;
окончание сессии не удаляет данные. Второй мессенджер привязывается после подтверждения
из существующего аккаунта. Существующие независимые аккаунты не объединяются по имени.
Телефон магазина продавец вводит отдельно. Вход не подписывает на рассылку.

Проверены на настоящем PostgreSQL: вход обязателен, VK/прочие провайдеры не допускаются
в кабинет продавца, один магазин при параллельных запросах, права владельца, фото,
товары, согласие, одобрение и появление товара в поиске. В браузере проверены формы,
выход и повторный вход, восстановление магазина, привязка второго мессенджера.
Транспорт подтверждения в автоматических тестах имитируется.

Живые боты проверены read-only: @NaydiGO_Bot и MAX отвечают на запросы личности;
обработчики подтверждений указывают на production. Локально нет webhook secrets,
и серверные обработчики не видят запросы локальной PostgreSQL. Поэтому перед
production-выкладкой нужен живой контрольный вход на тестовом HTTPS-backend,
связанном с той же базой, где начинается вход. Production-настройки не изменялись.
