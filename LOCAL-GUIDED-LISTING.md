# Локальная проверка объявления с помощником

Открыть http://localhost:3001/sell после `npm run dev`.
Для совместного теста доступна кнопка «Проверить локально без бота».
Это отдельный локальный демонстрационный аккаунт, НЕ вход через Telegram/MAX.
Маршрут возвращает 404 в production и для чужого хоста; права администратора не выдаёт.
Уведомления владельцу не отправляются из объявлений этого demo-аккаунта.

Три шага: товар и цена → место и продавец → проверка. Общая форма для человека и компании; прежние /connect и /business-demo ведут на /sell.
Состояние не выбирается за продавца. Цена: фиксированная, договорная (NULL),
бесплатно (0). Категория предзаполнена, её можно уточнить. Контакт и место
из существующего профиля подставляются повторно и могут быть изменены в той же форме. Новый адрес нужно выбрать
из геоподсказок и проверить на карте, автоматического угадывания координат нет.

Черновик сохраняется в PostgreSQL listing_drafts с версией и владельцем.
Черновики чужих аккаунтов недоступны; устаревшая вкладка получает 409.
После перезагрузки поля восстанавливаются, согласие на публикацию не восстанавливается.
Успешная публикационная заявка атомарно удаляет только соответствующий черновик.
Повтор запроса с тем же ID не создаёт второй товар и также очищает его черновик.

Найди-помощник объясняет шаги и отвечает на вопросы в тексте. По описанию
предлагает название, описание и категорию. Цена/состояние берутся только из
явных слов продавца, а не из догадок модели. Предложение применяется только
по кнопке; при изменении полей после запроса устаревшее предложение блокируется.
Адрес, телефон, регистрация и отправка объявления не выполняются моделью.
Ни телефон из профиля, ни координаты автоматически не передаются модели.
При отказе AI остаются форма, подсказки и сохранение черновика.

Реальный локальный запрос к настроенному AI прошёл: по описанию велосипеда
получены название/описание, явно указанные б/у и 5500 рублей. Боты не вызывались.

Проверки:
- npm run test:listing-guide — обязательные поля и извлечение явных фактов;
- npm run test:seller:postgres — записи/черновики, права, версии, договорная цена,
  очистка при отправке, ограничения помощника и запрет demo-входа в production;
- node scripts/browser-private-listing.mjs http://localhost:3002 — браузерная
  проверка собранной версии (сервер запустить отдельно npm start -- --port 3002).
  Проверены 390/1440 px, предложение без автозаполнения, явное применение,
  защита ручных изменений, восстановление полей, договорная цена, карта,
  согласие, отсутствие автоотправки и отказ AI без потери введённых значений.

Переписка покупателя с продавцом отложена по решению владельца проекта.

## Быстрое создание по фото
После загрузки фото доступна кнопка «Создать карточку по фото». По первому снимку
помощник предлагает название, описание и категорию. Можно сначала добавить текстовую
подсказку. Снимок уменьшается до 1280 px и передаётся модели только по кнопке.
Изменения применяются явно; замена фото или правка полей блокирует старое предложение.
Состояние и цена не угадываются по изображению. Контакт и место повторно берутся из
профиля, если он уже создан. Публикационный процесс и ручное одобрение не менялись.

Живая проверка: синтетическое изображение красной кружки → «Кружка красная»,
«Красная кружка с ручкой», «Кухонные принадлежности»; цена и состояние отсутствуют.
Новый помощник по умолчанию использует qwen/qwen3-vl-30b-a3b-instruct: предыдущая
vision-модель вернула upstream rate limit. Настройка ROUTERAI_VISION_MODEL сохранена.
HTTP 200 с вложенной ошибкой провайдера теперь учитывается как неуспешный запрос;
автоматического повтора нет. Проверка: node scripts/test-router-upstream-error.mjs.
Живая проверка вручную (один платный вызов): node scripts/check-local-listing-photo.mjs.

## Единый кабинет
Компания отмечается на втором шаге; дополнительно вводится только её название.
Профиль продавца/магазина создаётся атомарно вместе с первым товаром. Вторую организацию
или вторую точку система не создаёт. На странице видны объявления, статусы, редактирование
и снятие. Правки товара используют PUT /api/listings и сохраняют ID карточки. Изменение
общего контакта, типа продавца, названия компании или точки отправляет профиль на
повторное одобрение. Цена и сведения о товаре проверяются продавцом перед отправкой.
Старые загруженные/импортированные фото можно сохранить при редактировании только
внутри своего товара; чужие фото и чужие объявления недоступны.

Форма магазина с отдельной регистрацией и выбором импорта убрана из основного пути.
Существующие данные и API импорта не удаляются. В поиске опубликованные объявления
продавцов получили более крупные фото и отдельную кнопку карты рядом с маршрутом.
Оценки не выдумываются; реальная система отзывов в этот этап не входила.

Дополнительно проверено на PostgreSQL: компания создаётся через первый товар,
второй товар использует тот же профиль; редактирование не дублирует карточку;
изменение адреса скрывает профиль до одобрения; поиск после одобрения возвращает
обновлённую цену/точку; снятые товары компаний повторно не публикуются модерацией.
Браузерный тест охватывает человека/компанию на 390/1440 px и переходы старых URL.
