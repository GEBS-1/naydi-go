# Подготовка входа покупателей: Яндекс ID, Telegram, MAX

Проверено по официальной документации 28.09.2026. Это инструкция подготовки: новые обработчики входа покупателей **ещё не реализованы**, указанные ниже callback-адреса — согласованный здесь проект адресов для следующего этапа. Их регистрация у провайдера сама по себе не подключает вход. Кабинет владельца и текущая авторизация не заменяются.

Поиск остаётся доступным гостям. Вход нужен для добровольного переноса избранного и подборок между устройствами; не даёт прав администратора или владельца магазина.

## Общие данные

- Название: **НайдиGo**.
- Сайт: `https://naydigo.prepromo.ru/` (если домен изменится, обновить все разрешённые адреса).
- Описание: «Поиск товаров, услуг и магазинов по городам России. Сохраняйте находки и подборки, переходите к продавцам и стройте маршруты».
- Логотип: существующий знак НайдиGo; квадратный файл для аватара.
- Контакт: рабочая почта владельца. Нужны действующие страницы политики конфиденциальности и пользовательских условий — не указывать несуществующие ссылки.
- Секреты хранить в серверном менеджере секретов или локальном `.env.local`, не в Git, скриншотах и переписке. В браузер секреты не отправлять.

## Яндекс ID

1. Под своим постоянным аккаунтом откройте [создание приложения для авторизации](https://oauth.yandex.ru/client/new/id/).
2. Название «НайдиGo», описание выше, логотип, контактная почта; платформа — веб.
3. Основной адрес сайта: `https://naydigo.prepromo.ru/`.
4. Redirect URI для будущего серверного обработчика: `https://naydigo.prepromo.ru/api/auth/yandex/callback`. Без `#`, параметры маршрутов интерфейса сюда не добавлять.
5. Оставьте минимально необходимые права на профиль. Email — только если будем использовать его для контакта/восстановления; телефон и дату рождения для обычного входа не запрашиваем.
6. Сохраните Client ID и Client secret. Для публичного запуска пройдите верификацию сервиса, иначе Яндекс может показывать предупреждение.

Планируемые серверные переменные: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `AUTH_BASE_URL`. Пока приложение их не читает. На следующем этапе сервер обменивает код на токен, получает подтверждённый ID пользователя и создаёт собственную сессию; email из браузера не является доказательством личности.

[Официальная инструкция Яндекса](https://yandex.ru/dev/id/doc/ru/register-auth).

## Telegram

1. Откройте официальный [@BotFather](https://t.me/BotFather), создайте бота через `/newbot`.
2. Отображаемое имя: «НайдиGo». Вариант username: `naydigo_search_bot` или `naydigo_app_bot` — только если свободен. Это предложения, доступность не проверена.
3. Установите наш логотип и описание. Сохраните токен бота на сервере, не отправляйте его пользователям.
4. В мини-приложении BotFather выберите бота → **Login Widget**. Зарегистрируйте Allowed URLs:
   - `https://naydigo.prepromo.ru`
   - `https://naydigo.prepromo.ru/api/auth/telegram/callback`
5. В том же разделе получите **Client ID и Client Secret для входа**. Они не заменяются обычным токеном бота.

Для сайта выбран OIDC Authorization Code + PKCE, минимальные права `openid profile`, без номера телефона и разрешения на рассылку по умолчанию. Будущие переменные: `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET`; `TELEGRAM_BOT_TOKEN` нужен отдельно для функций самого бота. На сервере обязательны проверка JWT, issuer/audience/nonce/срока действия и одноразовый state.

Для кнопки входа не требуется загружать исходники в Telegram или запускать поискового чат-бота. Приложение продолжает работать на вашем сервере. Обработчик команд и webhook нужны, если отдельно подключим сообщения боту; они пока не реализованы.

[Официальный Telegram Login](https://core.telegram.org/bots/telegram-login), [создание ботов](https://core.telegram.org/bots/features).

## MAX

1. Откройте [MAX для партнёров](https://business.max.ru/). Нужен подтверждённый профиль российского юрлица, ИП или самозанятого; обычному физлицу верификация сейчас недоступна.
2. Создайте бота в разделе «Чат-боты». Название «НайдиGo», описание выше. Логотип: квадрат 500×500, PNG/JPG, до 5 МБ.
3. Никнейм сейчас формирует платформа автоматически — не рассчитывайте свободно выбрать `naydigo_bot`.
4. Пройдите модерацию. После неё получите токен бота и доступ к настройкам мини-приложения.
5. Для будущей интеграции указываем HTTPS-адрес приложения на нашем сервере. Конкретный отдельный entrypoint подготовим в коде: текущий сайт использует hash-навигацию, а MAX передаёт стартовые данные через URL-фрагмент, их нельзя потерять при запуске.

MAX-вход планируется через мини-приложение и проверку подписанных `initData` на сервере (`MAX_BOT_TOKEN`), а не доверие переданному `user.id`. Нужны проверка возраста данных и защита от повторного использования. Вход с обычного браузера через подтверждение в боте потребует отдельного одноразового сценария; универсальную кнопку OIDC для MAX здесь не предполагаем.

[Создание бота](https://dev.max.ru/docs/chatbots/bots-create/create), [подключение профиля](https://dev.max.ru/docs/maxbusiness/connection), [мини-приложения](https://dev.max.ru/docs/webapps/introduction), [валидация данных](https://dev.max.ru/docs/webapps/validation).

## Что передать для следующего этапа

Достаточно сообщить итоговый домен, username Telegram-бота, готовность Яндекс-приложения и статус MAX-профиля. Секреты вне чата положить в серверное окружение после согласования окончательных имён переменных. Следом реализуем и проверим вход, выход, срок сессии и перенос локальных сохранений только по явному согласию. Аккаунты разных провайдеров нельзя автоматически объединять по совпавшему имени/email.

Регистрация не подключает рекламную сеть. Реклама — отдельная интеграция; для гостевого бесплатного поиска она не требует обязательного входа.
