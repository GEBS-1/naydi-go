# Переписка покупателя и продавца

Рабочая версия выложена 03.11.2026: https://naydigo.prepromo.ru/messages.
Релиз 20261103T100012Z. Перед миграцией создана резервная копия PostgreSQL и фото.

У опубликованных собственных объявлений подключённого продавца есть кнопка
«Написать продавцу». Она открывает /messages?product=ID. До переписки требуется
вход через Telegram или MAX. Для внешних предложений и витрин без владельца
чат недоступен: остаются опубликованные контакты и источник.

На /messages находятся диалоги покупателя и продавца. Непрочитанные отмечены
числом. Текстовые сообщения — до 2000 символов. Видимая страница обновляется
каждые 5 секунд; скрытая вкладка не опрашивает сервер и не отмечает сообщения
прочитанными. После открытия полученного сообщения отправитель видит отметку
«Прочитано». Старые сообщения и диалоги загружаются порциями, по курсору.

Данные: PostgreSQL, chat_threads и chat_messages, миграция 0004_worthless_cerise.sql.
Диалог уникален для пары товар/покупатель; участники проверяются на сервере при
каждом запросе. Профиль магазина определяет продавца, клиент не назначает его сам.
Третий аккаунт получает 404. GET не меняет прочтение; POST read подтверждает
конкретные сообщения только от имени получателя. Изменения требуют same-origin.
Тело запроса ограничено по фактическим байтам, действуют лимиты записи.

Сообщение имеет клиентский UUID: повтор после сетевого сбоя сохраняет его один раз.
Текст при сбое остаётся в форме. Переписка сохраняется после снятия/удаления товара;
для удалённого товара остаётся снимок названия, продавца и города, без битого перехода.
Новые диалоги нельзя начать по скрытым, снятым, тестовым или неподключённым товарам.
AI не читает переписку. Файлы, пуши и сообщения в Telegram/MAX в этот этап не входят.
Существующие старые обращения с одним ответом не удалены.

## Рабочий путь

1. Открыть объявление продавца, размещённое в НайдиGo, и нажать «Написать продавцу».
2. Войти через Telegram или MAX. После входа откроется тот же диалог.
3. Продавец отвечает в /messages; ссылка есть в его кабинете и в навигации покупателей.

В пользовательском интерфейсе отсутствуют демонстрационные входы и тестовые роли.
Служебный локальный сценарий остаётся только в scripts/browser-chat.mjs: он создаёт
изолированные демонстрационные аккаунты через dev-only API. Эти endpoints возвращают
404 в production. Неопубликованные локальные данные и сообщения сценария не переносятся
на сервер. Тестовый текст не отправляется реальным людям или в боты.

## Проверки

- npm run test:chat:postgres — настоящая PostgreSQL в удаляемой изолированной схеме:
  права, два направления, повторные запросы, параллельное открытие, прочтение,
  страницы истории, другой способ входа того же аккаунта, снятие/удаление товара,
  запрет демонстрационного входа в production.
- npm run test:chat:browser — настоящее локальное приложение и PostgreSQL, две
  независимые браузерные сессии 390/1440 px. Только тестовые аккаунты. Проверены
  обмен, автообновление, прочтение, перезагрузка, недоступность третьему аккаунту,
  сохранение текста при искусственном сетевом сбое и повтор с тем же UUID.
- npm run test:seller:postgres — регистрация и размещение объявлений.
- node scripts/test-nearby-focus.mjs http://localhost:3001 — поиск, геолокация,
  карта/маршруты, ссылка в чат у объявления.

В браузерном тесте имитируется только один сетевой отказ отправки. Успешная
переписка проходит через настоящий локальный API и базу. Живые боты не вызываются.
