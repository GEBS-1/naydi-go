# Настройка администратора и сверка расходов

## Cloudflare Access (выполняет владелец сервера)

1. Создать Zero Trust / Access self-hosted application для административных путей своего домена: `/onboarding`, `/connections`, `/api/onboarding`, `/api/search-admin`. Добавить Allow policy только для администраторского email через проверяемый IdP/одноразовый email-код. Не включать bypass или Everyone.
2. Вписать на сервере `AUTH_ACCESS_ISSUER=https://<team>.cloudflareaccess.com` (без завершающего слеша), `AUTH_ACCESS_AUD` из Application Audience и `ADMIN_EMAIL` проверенного администратора. Эти настройки не считываются из клиентского запроса. Dev mock не использовать.
3. Обеспечить передачу `Cf-Access-Jwt-Assertion` от Access в приложение. Оно проверяет RS256, JWKS, issuer, audience, срок действия, sub/email и тип app. Не преобразовывать произвольный email клиента в доверенную личность. В production неподписанные `oai-authenticated-user-*` не принимаются даже при `AUTH_TRUSTED_PROXY=1`.
4. Исключить обход защиты через другой hostname/Worker URL; даже прямой вход без корректного JWT должен получить отказ административного API. Сохранить HTTPS. Не блокировать покупательский `/api/search` обязательной авторизацией.
5. `/api/connect` смешанный: POST общедоступен для заявки, GET/PATCH требуют администратора. Не закрывать весь endpoint простой Access-политикой, иначе сломается публичная заявка. Для админских вызовов с `/connections` убедиться, что доверенный gateway передаёт валидный assertion и на этот путь (например, метод-зависимые правила reverse proxy). Не заменять это доверием к email-заголовку.
6. Владелец магазина использует отдельную D1-сессию `ng_owner`, не администраторский JWT. Проверить её Secure/HttpOnly/SameSite=Lax cookie, одноразовое приглашение, отзыв при выходе и запрет чужого store_id. Покупатель ищет без регистрации.
7. Проверить staging вручную: неподписанные headers → отказ; токен другого приложения/пользователя → отказ; разрешённый администратор → успех. Локальные тесты подписанных тест-токенов не подтверждают настройки вашего Access.

Документация проверки JWT: https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/
