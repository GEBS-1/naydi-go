# ИИ-подборки НайдиGo

Локальная настройка: `.env.local` в корне `naydi-go` (игнорируется Git):

```dotenv
ROUTERAI_API_KEY=ваш_новый_ключ
ROUTERAI_MODEL=qwen/qwen3-30b-a3b-instruct-2507
```

После изменения перезапустите `npm run dev`. Откройте `http://localhost:3000/#plan`, опишите задачу, создайте подборку и нажмите «Разобрать задачу с ИИ». Модель можно заменить идентификатором RouterAI с поддержкой Chat Completions и JSON Schema. Jev использует Decisions API и не подходит для генерации списков.

Ключ используется только сервером. В production задайте ROUTERAI_API_KEY через секреты Worker, ROUTERAI_MODEL через его переменные; не копируйте `.env.local` в публичные файлы. Ключи, отправленные в переписке, следует отозвать и заменить.

Список сохраняется в D1, доступ ограничен HttpOnly-cookie гостя. Очистка cookie лишит браузер доступа к ранее созданным спискам. Миграция 0002 применяется `npm run db:local` после сборки. Существующие магазины не изменяются.

ИИ предлагает поисковые позиции и уточняющие вопросы, не создаёт товары и не подтверждает цены или наличие. Кнопка «Найти предложения» использует только опубликованные реальные записи общей базы; приватные черновики и демо исключены. Это не общий чат и не интернет-поисковик. Brave Search требует отдельного подключения. При ошибке API сохранённый список доступен для ручного редактирования.

Ограничения расходов: до 3500 выходных токенов за вызов, 20 попыток ИИ-разбора в час на всё приложение, таймаут 45 секунд, без автоматических повторов. Перед публичным запуском дополнительно установите бюджет ключа у провайдера; приложение не обеспечивает денежный лимит расходов.

Проверки: `node scripts/test-plan-ai.mjs` (без сети и расходов), `node scripts/test-plan-ai.mjs --live` (один платный запрос с локальным ключом). Скрипты не выводят ключ или тела ошибок провайдера.
